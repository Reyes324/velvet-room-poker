# 打法点评（本场之最）—— 设计文档

**日期**：2026-09-08
**状态**：设计已定，待写实施计划
**提出人**：用户（产品设计）

---

## 一句话

一局游戏结束、账本自动弹出时，在账本里加一段"颁奖式"的打法点评：根据这个房间打过的所有牌，给几个打法上最突出的人各贴一个标签（如"影帝""秒怂"）。不是数据表，是几条损友互相调侃式的短评。

---

## 背景 / 要解决的问题

- 想让朋友们打完看到"谁最怎样"——谁爱诈唬、谁太紧、谁一凶就怂。
- 现在每手牌只存了结果（谁赢、赢多少、公共牌、摊牌底牌、每人输赢），没存逐动作，所以这些打法指标现在算不出来。
- 人机对战那边已有类似机制（`pveStore` 的 `oppStats` + `_opponentReads()`），但那是给 AI 读人用、不展示、只跟踪人类一个玩家。多人这边完全没有。

---

## 范围

**做**：
- 多人房间的对局数据。
- 后台边打边累加每个玩家的打法计数器，跨这个房间所有牌（跨多场游戏）。
- 一局游戏结束时，在账本里显示"本场之最"点评段。

**不做（YAGNI / 明确排除）**：
- 人机对战（数据源只有多人房间）。
- 打牌当中查看（不做实时 HUD——会改变靠观察读人的乐趣、也让常看的人占便宜）。
- 独立的"打法画像"面板 / 每人一张完整数据表。就账本里几条短评。
- 长期 / 跨房间画像。数据随房间生命周期，房间散了或服务重新部署就清空，**不做持久化、不做快照**（跟牌局记录、账本、聊天记录同一个生命周期，可接受）。
- 精确百分比对外展示。点评是"本场观察到的行为对比"，不承诺统计学可信。
- "剔除自己出点评"（opt-out）——v1 不做，全员公开（用户 2026-09-08 拍板）。

---

## 展示方式

### 位置

**账本里新增一段"本场之最"**。

理由（用户拍板）：用户经常直接退出、不回等待室，所以不能把它放在等待室或独立面板。一局游戏结束时账本会自动弹出（`RoomPage` 的 `game:ended` handler，`hostEnded` 时 `setShowLedger(true)`），这是唯一能保证大家都看到的时刻。

**配套小修**：计时游戏到点自动结束时（`hostEnded: false`）账本目前不自动弹。这段点评的全部价值就在"保证被看到"，所以计时结束也让账本带着点评自动弹一次。

### 内容形态

账本原有的盈亏表 + 拍一拍统计不动，下面加一段：

```
本场之最
  影帝        阿强   —— 空手大举下注 4 次，面不改色
  养生局      小明   —— 入池率 18%，非大牌不玩
  我倒要看看   老野   —— 摊牌率 71%，几乎不弃牌
  梭哈人格    Teddy  —— 进攻性拉满
```

- 每条：奖名 + 人名 + 一句大白话依据。
- **每人最多一个奖，不叠**（用户拍板）。
- 没啥特点的人不出现——不是每人都发。
- 一条都撑不起（这场手数太少 / 没人达到任一门槛）→ 整段写"这场手数还少，没看出谁特别怎样"。
- 大赢家 / 大输家账本盈亏表本来就一眼看得出，不重复发奖。

### 可见范围

- **房间里所有人都能看到所有人的点评，全员公开。** 点评由服务端算一次，全桌看到的是同一份。
- **v1 不做"剔除自己"的开关**（用户 2026-09-08 拍板先去掉）。以后想加，是在服务端算奖时按 playerId 跳过某人，纯增量，不影响 v1 结构。

---

## 奖项清单

每场从下面挑**撑得起门槛的**发。

| 奖名 | 行为 | 触发（谁得） | 小门槛（不够则这条不出现） |
|---|---|---|---|
| **手痒星人** | 什么牌都下场玩 | 入池率最高 | 在场每人都打了 ≥15 手 |
| **养生局** | 很少下场、非大牌不玩 | 入池率最低 | 同上 |
| **梭哈人格** | 主动进攻最多 | 激进度（下注+加注 ÷ 跟注）最高 | 那人翻后 ≥10 次决策 |
| **牌桌 NPC** | 从不主动、只会跟 | 激进度最低 | 同上 |
| **我倒要看看** | 爱跟到最后比牌 | 摊牌率最高**且**明显偏高 | 那人 ≥15 次看到翻牌 |
| **秒怂** | 一遇进攻就弃 | 面对加注弃牌率最高 | 那人 ≥8 次面对加注 |
| **影帝** | 敢拿空气大举下注 | 空气开火次数最多 | 那人空气开火 ≥3 次 |
| **惯性开火** | 拿没拿到都开火 | 持续下注频率最高 | 那人当翻前加注方 ≥8 次 |
| **加你一脸** | 空手再加注顶人 | 空手 3-bet 次数最多 | ≥2 次（朋友局大概率没人达标，不出现） |

### 选谁 / 冲突顺延（用户拍板"每人一个奖"）

1. 先算出每个奖的候选得主（该维度最极端的人）。
2. 一个人若同时是多个奖的得主：**留他最突出的那个**（跟同桌其他人差距最大的那条，用标准化后的差距比较），其余奖顺延给下一名合格的人——够门槛就给、不够就这条不出现。
3. 结果是一份每人至多一个标签的短名单。

## 指标怎么算

所有指标由**服务端**在每手结束时增量累加进 `Room` 上的一份 per-player 计数器；一局游戏结束时服务端算出奖项列表，随 `game:ended` / 账本数据一起发给客户端，客户端只负责渲染。

### 需要新增的原始记录

现在 `action:happened` 事件实时广播但**打完就扔**。新增：每手把逐动作序列（谁、哪条街、动作、金额、当时底池）连同已有的每人底牌（`allHoleCards`，每手都存、不只摊牌）喂给计数器累加逻辑，**累加完即可丢弃逐动作序列**（不长期存原始动作，只留固定大小的计数器）。

### 每个计数器字段（草案，实施计划里定死）

按 `playerId`：
- `handsDealt`：被发牌的手数
- `handsVPIP`：这手主动往池里放过钱（跟大盲、加注、再加注都算；只发盲注不算）的手数 → 入池率 = `handsVPIP / handsDealt`
- `handsPFR`：这手翻前主动加注过的手数 → 翻前加注率
- `postflopBets` / `postflopRaises` / `postflopCalls`：翻后的下注 / 加注 / 跟注次数 → 激进度 = `(bets+raises) / calls`（`calls` 为 0 时特殊处理，避免除零）
- `postflopDecisions`：翻后总决策次数（门槛用）
- `sawFlop`：看到翻牌的手数
- `wentToShowdown`：看到翻牌后打到摊牌的手数 → 摊牌率 = `wentToShowdown / sawFlop`
- `facedRaise` / `foldedToRaise`：面对加注的次数 / 其中弃牌的次数 → 面对加注弃牌率
- `airFires`：转牌/河牌所有主动下注加注中、手牌比"底对/没对没听牌"还差的次数；**加上**翻牌圈**非持续下注**的空气进攻
- `cbetOpportunities` / `cbets` / `cbetAir`：当翻前加注方进到翻牌的次数 / 其中翻牌下注的次数 / 其中是空气的次数 → 持续下注频率
- `light3bets`：翻前面对别人加注、自己拿弱牌再加注的次数

### "空气"判定

用 App 里已有的牌力评估函数（`pveStrategy` 的 `computeEquity` / 手牌评估），算玩家开火那一刻的牌对着当时公共牌的强度，**比"底对 / 没对没听牌"还差**记为空气。半诈唬（拿听牌打）**不算**空气——标签更干净。

### "持续下注"判定

需要知道这手翻前最后一个加注的人是谁（逐动作序列里有）。翻牌圈由这个人主动下注 = 持续下注，从"诈唬（影帝）"里排除、单独计到"惯性开火"。翻牌圈**非**持续下注方的空气进攻（空气 check-raise、空气 donk bet、空气反加）仍算进 `airFires`。

### 翻前不单列诈唬

翻前拿烂牌加注 = "松凶"，已被入池率 + 翻前加注率覆盖，不重复算。唯一算翻前诈唬的是空手 3-bet（"加你一脸"），单列。

### 门槛哲学（用户拍板"宽容点"）

没有硬性 80 手线。改成：
- 整段显示的前提：这场至少打了 ~15 手。
- 每条奖项各自的小门槛（见清单表）——够就发、不够就这条静默跳过（不写"样本不足"）。
- 措辞本身带"本场"，不承诺是长期画像，几十手也说得过去。

---

## 数据 / 重置行为

- 计数器活在 `Room` 实例上，随房间生命周期。房间散了或服务重新部署 → 清空。
- **不做持久化、不做定期快照**（跟牌局记录/账本/聊天记录一致；这是"本场/近期"点评，不是历史追踪，重置可接受）。
- 数据量非问题：计数器是每人固定几十个整数字段，不管打多少手都是固定大小；逐动作序列累加完即弃。

---

## 分单元（便于写实施计划）

1. **动作记录累加器**（服务端，新模块）：吃"这手的逐动作序列 + 每人底牌 + 公共牌"，吐"更新后的 per-player 计数器"。纯函数式、可单测（喂构造好的手、断言计数器）。不依赖 socket。
2. **奖项计算器**（服务端，新模块）：吃"一桌人的计数器 + 在场玩家名单"，吐"奖项列表（奖名 + playerId + 依据文案）"，含门槛过滤 + 每人一个奖的冲突顺延。纯函数、可单测。
3. **接线**（服务端 `index.js`）：`Room` 挂计数器；每手结束调累加器；`game:ended` 时调奖项计算器，把结果随账本数据发出；计时结束也让账本弹。
4. **渲染**（客户端 `LedgerModal.jsx`）：账本盈亏表下加"本场之最"段。

---

## 验证思路

- 累加器 / 奖项计算器：服务端单测。构造几手确定性的牌（复用现有 seeded random 的做法），喂进去断言计数器字段 + 断言奖项结果（含"每人一个奖""门槛不够则跳过""一条都撑不起则整段兜底文案"）。
- 端到端：两个真实浏览器 context 打若干手、房主结束游戏，断言账本里"本场之最"段渲染出来、内容跟服务端算的一致。
- 计时游戏到点结束 → 账本带点评自动弹。
- 回归：现有账本盈亏表 / 拍一拍统计不受影响。

## 待实施计划里定死的细节

- 计数器字段的精确清单与命名。
- "明显偏高"（"我倒要看看"）的具体判据——比同桌中位数高多少。
- "差距最大"（冲突顺延）用什么标准化方式比较不同量纲的指标。
- 依据文案模板（每个奖一句，带不带具体数字）。
- 一场最多显示几条奖（建议上限 4–5，取门槛达标里最突出的几条）。
